Mahjong Soul traffic inspection and local cosmetic customization, built with Python and mitmproxy.

## Features

- Capture a selected local process and decode WebSocket protobuf messages.
- Inspect original and actual message content, wire bytes, and processing actions.
- Apply local character, skin, title, emoji, and appearance settings through existing game controls.
- Use the English, Japanese, or Simplified Chinese GUI, with system-language detection and HiDPI support.
- Check and update protocol/cosmetic resources, including offline rebuilding from cached bundles.

## Downloads

| Platform | Package |
| --- | --- |
| Windows x64 | `windows-x64-installer.exe` or `windows-x64-portable.zip` |
| macOS Apple Silicon | `macos-arm64-portable.tar.gz` |
| macOS Intel | `macos-x64-portable.tar.gz` |
| Linux x64 / ARM64 | Matching `linux-*-portable.tar.gz` |
| Python 3.14+ | Wheel or source distribution |
| Docker x64 / ARM64 | Matching `linux-*-docker.tar.gz`, loaded with `docker load` |

Keep the entire portable folder together. Update resources on first use, select the game process, and start capture. Local cosmetics are enabled by default in the GUI; CLI capture is read-only unless `--cosmetics` is supplied. Cosmetics are local and do not grant server-side ownership or change other players' views.

Every package has a `.sha256` file. `SHA256SUMS` covers all release packages.

## Validation and limitations

- All five desktop targets passed 120 core tests, 18 GUI checks, and frozen startup/worker checks in GitHub Actions. Both Docker architectures passed dependency diagnostics.
- Windows installer compilation is verified; actual installation, upgrade, and uninstallation still need user testing. Real game/cosmetic coverage remains incomplete.
- Windows downloads are unsigned. macOS applications use ad-hoc signing and are not notarized; operating-system trust checks may require additional user action.
- Local capture needs platform-specific privileges. Linux local capture requires kernel 6.8+; package compatibility alone does not establish interception support.
- Plain WS needs no interception CA; verified WSS generally requires explicit client trust. The application never installs trust automatically.
- Docker currently supports resource preparation and diagnostics; a central HTTP/SOCKS proxy server is deferred.
